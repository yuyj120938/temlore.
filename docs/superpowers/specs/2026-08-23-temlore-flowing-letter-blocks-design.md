# Temlore 连续信纸内容块设计

## 目标

把现有的“整段文字 + 浮动照片坐标”编辑方式改为连续信纸内容流。用户可以写一段文字、插入照片，再在照片下继续写。编辑页、存稿和阅读页使用相同的内容顺序，彻底避免照片覆盖文字。

本次只调整信件正文与照片的编辑、保存和阅读方式，不改登录、封存时间、封信动画、桌面抽屉或 Start 页面。

## 已确认的视觉方向

- 使用 A「连续信纸」方案，不显示明显的内容块边框。
- 信纸保持纯白，不增加横线。
- 界面保持现有手机比例和 Temlore 已确认的色彩、字体工具栏与纸张风格。
- 内容按自然文档流从上往下增长，长信由页面纵向滚动承载。

## 编辑交互

### 文字

- 整个正文书写区域可点击。
- 点击已有文字时，光标进入对应位置；按回车正常换行。
- 点击正文末尾的空白区域时，光标进入最后一个文字块继续输入。
- 字体仍可在宋体与楷体之间切换，并作用于整封信。

### 插入照片

- 点击工具栏“照片”后，从手机相册选择真实图片。
- 照片插入当前光标位置。
- 如果光标位于文字中间，当前文字块拆成“光标前文字”和“光标后文字”，照片块放在两者之间。
- 插入成功后，照片下方始终存在一个文字块并自动获得焦点，用户可以立即继续写。
- 如果当前没有有效光标位置，照片追加到信件末尾。
- 用户取消相册选择时，不创建空照片块。

### 照片调整

- 保留照片框长宽调整。
- 保留照片内部画面的缩放。
- 照片可以在自己的内容行内左右移动。
- 不允许照片跨越内容块上下移动，以免覆盖相邻文字。
- 编辑状态下照片右上角显示淡色删除按钮 `×`；删除立即生效，不弹二次确认。
- 阅读状态不显示编辑控件。

## 内容模型

新信件按顺序保存内容块，而不是分别保存正文与照片：

```ts
type LetterBlock =
  | { id: string; type: 'text'; text: string }
  | {
      id: string;
      type: 'photo';
      url: string;
      caption: string;
      scale: number;
      width: number;
      height: number;
      alignX: number;
    };
```

`EditorDraft` 和 `StoredLetter` 保存有序 `blocks`。照片的 `alignX` 只表示其所在内容行内的水平位置，不再保存可跨越文字的垂直位移。

实现应保持数据结构最小，不引入独立富文本库或新依赖。

## 存稿与封存

- 编辑过程中，每次文字、字体、照片或顺序变化都沿用现有本地自动存稿机制。
- 从编辑页返回 Start 后，再次进入会恢复相同内容块顺序及照片设置。
- 完成封存后清除当前手机号对应的存稿。
- 封存完成后再次点击 Start writing 创建新信，不继承已封存内容。

## 阅读与旧信兼容

- 阅读页按照 `blocks` 原始顺序渲染文字与照片，二者都参与正常文档流。
- 文字块保留换行；照片块占据真实垂直空间，因此不会与文字重叠。
- 阅读页保留照片尺寸、内部缩放、水平位置和说明。
- 阅读页继续支持长信纵向滚动。
- 旧信如果只有 `body` 和 `photos`，读取时转换为安全顺序：一个正文文字块在前，所有照片块依次在后。
- 旧照片不再应用历史 `y` 垂直偏移；水平位置在容器范围内转换或收敛，确保旧信可读且不覆盖正文。
- 兼容转换可以在读取或渲染边界完成，不要求破坏性重写用户的 localStorage 数据。

## 边界情况

- 空信件至少保留一个空文字块。
- 连续插入多张照片时，每张照片按插入顺序保存，并保证末尾有可继续输入的文字块。
- 删除位于两个文字块之间的照片后，相邻文字块合并或保持连续可编辑效果，不留下不可点击的空隙。
- 载入缺少新字段的旧存稿或旧信时使用安全默认值，页面不能崩溃。
- 图片文件过大导致本地存储失败时，沿用现有容错：当前编辑仍可继续，但不额外引入上传服务。

## 验收标准

1. 在一段文字中间插入照片，照片前后的文字顺序正确。
2. 照片插入后焦点来到其下方，可以立即继续写字。
3. 照片可调整长宽、内部缩放和水平位置，但不能覆盖上下文字。
4. 删除照片后内容流保持连续。
5. 返回 Start 并重新进入，文字、照片和顺序完整恢复。
6. 封存并打开后，阅读页顺序与编辑页一致，无文字与照片重叠。
7. 长信可完整向下滚动。
8. 旧格式信件仍可打开，并以正文在前、照片在后的安全布局显示。
9. 封存完成后新建信件不会继承上一封信的内容。

## 验证方法

- 为内容块的拆分、插入、删除、旧格式转换编写单元测试。
- 为编辑器添加存稿恢复、照片后继续输入及照片调整的组件测试。
- 为阅读页添加内容顺序和旧信兼容测试。
- 在 393 × 852 手机视口运行 Playwright 流程：写第一段 → 光标处插图 → 写第二段 → 封存 → 到达 → 打开阅读。
- 运行全量测试、TypeScript 生产构建和现有端到端测试，确认无回归。
